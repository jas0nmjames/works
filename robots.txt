# HOW THIS FILE WORKS
#   - Rules are grouped by "User-agent". A crawler obeys the MOST SPECIFIC
#     group that names it, and ignores all other groups - including the
#     "*" catch-all. So if you add a named group for a bot, that group must
#     be complete on its own.
#   - "Disallow:" with nothing after it means "allow everything".
#   - "Disallow: /" means "crawl nothing".
#   - This file is advisory. Well-behaved crawlers honor it; malicious
#     scrapers ignore it entirely. It is not a security control - never use
#     it to hide something. Anything genuinely private must not be deployed.
#
# CURRENT POLICY: allow everything, including AI crawlers.
# Rationale: this is a portfolio. Its entire purpose is to be found.


# --- Default: every crawler, full access ---------------------------------

# --- AI CRAWLERS ---------------------------------------------------------
# Listed explicitly for documentation, not because they need it - the "*"
# group above already permits them. They are written out so the decision is
# visible and easy to reverse later.
#
# There are TWO DISTINCT CLASSES here, and conflating them is the common
# and costly mistake:
#
#   1. TRAINING crawlers - collect pages to train future models.
#      Blocking these opts you out of training data. It does NOT reduce
#      your chances of being cited in AI answers.
#
#   2. RETRIEVAL / SEARCH fetchers - fetch pages live to answer a user's
#      question right now, usually with a link back to you.
#      Blocking these DOES remove you from AI-generated answers and
#      citations. For a portfolio, blocking these is self-defeating.
#
# To opt out of model training while staying citable, set "Disallow: /"
# on the class-1 agents ONLY and leave class 2 alone.
